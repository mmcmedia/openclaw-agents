# Validation Presenter Skill

**Purpose:** Format app research findings for McKinzie's review with clear go/no-go recommendations.

**Trigger:** After completing app opportunity research.

---

## 🎯 Output Goal

**One-page summary** that lets McKinzie decide in 60 seconds:
- Is this worth building?
- What's the evidence?
- What's the risk?
- What would she need to see to say yes?

## 🎨 Visual Formatting Tips

### Use Emojis for Scanability
- 🟢 / 🟡 / 🔴 for status
- ✅ / ❌ for pass/fail
- ⚡ for key insights
- 💰 for money
- ⚠️ for risks

### Keep It Short
- No paragraph longer than 3 lines
- Use tables for comparisons
- Use bullet lists for features
- Bold the key numbers

### Make Decisions Easy
- Default to BUILD / MAYBE / SKIP
- If MAYBE, say exactly what would change to BUILD
- Include "If you only read one thing" summary at top

---

## 📊 Scoring Rubric

### Go / No-Go Decision Tree

```
Pain Validation < 2/3?
  → SKIP (not enough evidence)

Market Validation < 2/3?
  → SKIP (market not viable)

Strategic Fit < 20/30?
  → MAYBE (need different angle)

Revenue Potential < $10K Year 1?
  → MAYBE (need bigger market or higher price)

All checks pass?
  → BUILD (with confidence level)
```

### Confidence Levels

| Level | Meaning | Next Step |
|-------|---------|-----------|
| 🟢 **High** | 90%+ chance of success | Build MVP immediately |
| 🟡 **Medium** | 60-70% chance | Landing page test first |
| 🔴 **Low** | <50% chance | Skip or pivot significantly |

---

## ✅ Quality Checklist

Before presenting to McKinzie:

- [ ] Can she understand the opportunity in 60 seconds?
- [ ] Is there clear evidence for every claim?
- [ ] Are risks honestly presented?
- [ ] Is the recommendation clear (BUILD/MAYBE/SKIP)?
- [ ] Are next steps obvious if she says yes?
- [ ] Is there a "what would convince you" for maybes?
